# 前后端联调设计

本任务执行用户已确认的业务方案和“开始修改”指令，沿用现有视觉；无需重新选择产品规则。

- 浏览器以原生 JavaScript 模块加载，复用已有页面、弹窗、筛选、指南和照片样式，不引入框架或构建依赖。
- API 模块统一 Cookie、每次写入获取 CSRF、ProblemDetails 错误以及未认证事件；前端配置默认同源 /api，开发服务器代理到 ASP.NET Core，正式环境由 IIS/Nginx 代理。
- 身份模块实现注册/登录/退出/账号状态、邮箱验证/重发/已验证邮箱恢复。邮件当前包含账号标识和令牌，页面支持粘贴，也支持 URL 查询参数预填；令牌不存本地缓存且预填后清除地址中的令牌。
- 动物模块用真实 API 分页查询并筛选，保留空状态与错误重试，不用示例动物冒充真实记录。本人管理支持草稿、编辑、上下架、上传/删除照片和三只上架提示，最终由 API 校验。
- 申请模块收集姓名、手机号必填、微信号选填、居住地、经验及理由；展示本人申请、本人动物收件箱和详情，发布者记录通过/拒绝。本人动物不提供申请入口；后端仍强制验证。
- 不把敏感申请保存在 localStorage、URL 或公共 DOM；退出/401 清空私人状态并关闭私人弹窗，提醒重新登录，未完成表单不自动重复提交。所有 API 内容进入 HTML 前统一转义，图片只采用服务器照片路径。
- 自动测试覆盖请求协议和错误；真实浏览器通过同源 HTTPS 代理连接隔离 MySQL 后端，验证注册、登录、邮件、发布/上下架、名额、图片、申请收件箱、隐私、退出和手机布局。服务器/数据库凭据均在仓库外。
- 单独前端联调 PR 依赖未合并的后端 PR #5，保留审核，不公开部署。
